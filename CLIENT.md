# Nan React Client

The `client/` folder contains the full Nan React application (Vite + TypeScript + Tailwind).
It replaces the legacy `index.html` / `app.html` / `app.js` files with a modern React SPA.

## Structure

```
Nan/
├── _server/          ← Express backend (Railway)
├── api/              ← API route handlers
├── client/           ← React frontend (this folder)
│   ├── src/
│   │   ├── components/
│   │   │   ├── layout/   AppShell, navigation
│   │   │   ├── pages/    Landing, Onboarding, Home, Wallet, Shop, Agent, Activity, Settings
│   │   │   └── ui/       Button, Card, Badge, Input, Spinner, Logo
│   │   ├── store/        nanStore.ts  (Zustand, persisted to localStorage)
│   │   ├── lib/          nan.ts  (typed API client for all backend routes)
│   │   ├── data/         products.ts  (demo product catalogue)
│   │   ├── utils/        format.ts
│   │   ├── App.tsx
│   │   ├── main.tsx
│   │   ├── config.ts     wagmi config (Arc Testnet)
│   │   └── index.css
│   ├── index.html
│   ├── vite.config.ts
│   ├── tsconfig.json
│   └── package.json
├── dist-client/      ← Build output (git-ignored, generated by npm run build:client)
├── vercel.json       ← Routes /api/* to Railway, everything else to React SPA
└── CLIENT.md         ← This file
```

## Local development

**Terminal 1 — Nan backend:**
```bash
npm run dev          # starts Express on port 3000
```

**Terminal 2 — React client:**
```bash
cd client
npm install
npm run dev          # starts Vite on port 5173, proxies /api → localhost:3000
```

Open http://localhost:5173

## Build for production

```bash
npm run build:client   # builds client/ → dist-client/
```

Then deploy the whole repo to Vercel. `vercel.json` is already configured:
- `/api/*` → proxied to `https://nan-production.up.railway.app/api/*`
- `/*` → served from `dist-client/index.html` (React SPA)

## Environment variables

Create `client/.env.local` for local development:
```
# Optional: if you want to point at a different backend URL
VITE_NAN_API_URL=https://nan-production.up.railway.app
```

In production on Vercel, leave `VITE_NAN_API_URL` unset — `vercel.json` already proxies
`/api` to Railway so relative paths just work.

## How the API client works

`client/src/lib/nan.ts` is a typed wrapper around every Nan backend route:

```ts
import { signIn, getWallet, sendUsdc, getActivity, nanChat } from './lib/nan'

// Auth
const { token, walletAddress } = await signIn(email, otp)

// Wallet
const wallet = await getWallet(walletAddress, token)
// wallet.balance → "120.00"

// Send
const { txId } = await sendUsdc(from, to, amount, token)

// AI agent
const { reply } = await nanChat({ messages, usdcBal, userAddress, sessionToken })
```

When a user signs in with email OTP, their `sessionToken` and `walletAddress` are stored
in Zustand (`nanStore`) and persisted to localStorage. Every subsequent API call passes
the token in the `Authorization` header.
